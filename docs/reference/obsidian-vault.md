# Obsidian vault

A `tests/` tree opens directly as an Obsidian vault. Cases keep machine-readable
front-matter; `build-index` generates hub notes so the Graph and Backlinks views
connect every case to its requirements and suites.

See also: [Test-case format](test-case-format.md) · [Configuration](configuration.md).

## Node types

| Node | File | Generated? |
| --- | --- | --- |
| Test case | `tests/<suite>/<sub>/<ID>_<slug>.md` | no |
| Requirement proxy | `tests/_meta/requirements/<safe>.md` | yes |
| Suite/module MOC | `tests/<folder>/_index.md` (recursive) | yes |
| Vault root MOC | `tests/_index.md` | yes |
| Tag hubs | native Obsidian tags from `tags:` (nested via `/`) | — |

Generated notes **omit `id:`**, so the index, OQL, and coverage ignore them. They carry
a `generated by onetest-tms build-index` marker and are rewritten (stale ones pruned) on
every `build-index` run — never hand-edit them.

## How the graph connects (proxy→case)

Cases contain **no wikilinks**. The requirement↔case edge is drawn by the generated
**proxy note linking back** to each covering case as `[[<ID>]]` (resolved via the case's
`aliases: [<ID>]`). Obsidian graph edges are undirected, so opening a case shows its
requirements in the Backlinks pane and clusters it with sibling cases on the same
requirement. MOC notes link down the folder tree the same way.

## Requirement URLs

Requirement refs stay **bare** in `requirements:` (e.g. `OWNER/REPO#N`). The proxy note
derives a clickable GitHub URL: `OWNER/REPO#N` → `https://github.com/OWNER/REPO/issues/N`.
A bare issue number uses `default_requirements_repo` from `.onetest/config.yml` when set.

## External links (reachable, not graphed)

Automation/doc URLs are pure-URL front-matter properties (`automation_pr`,
`automation_url`, `doc_url`) — clickable in the Properties panel, no graph node.

## Regenerating

`bash onetest-tms/scripts/build-index.sh --dir tests --out index.json` (or the MCP
`build_index` tool) rebuilds `index.json` and regenerates all hub notes.
