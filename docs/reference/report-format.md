# Report & artifact formats

OneTest TMS writes several artifacts into the TM repo. This page documents their shapes so you (or
a dashboard, or another agent) can read and produce them reliably. Human reports are Markdown;
machine artifacts are JSON.

| Artifact | Path | Produced by |
| --- | --- | --- |
| Run report | `reports/RUN-<KEY>-YYYY-MM-DD-NNN.md` | `complete_run` |
| Coverage report | `reports/coverage.md` | `automation_coverage` |
| Automated launch | `reports/automated/<run>.json` | `ingest_results` |
| Correlation | `reports/correlation.json` | `correlate_results` |
| Case index | `index.json` | `build_index` |

---

## Run report — `reports/RUN-….md`

```markdown
---
run_id: RUN-SHOP-2026-05-29-001
suite: Cart smoke
environment: staging
date: 2026-05-29
---

| ✅ Passed | 1 | 50.0% |
| ❌ Failed | 1 | 50.0% |
| ⏸ Blocked | 0 | 0.0% |

### Size Distribution
| Size | Count |

| Case | Title | Size | Result |
|------|-------|------|--------|
```

  Distribution block is omitted when no case has a `size`. The Failed Tests block appears only when
  there are failures.

## Coverage report — `reports/coverage.md`

```markdown
# Automation Coverage

## Summary
| Metric | Count |
|--------|-------|
| Total test cases | 4 |
| Marked automated | 2 |
| ✅ Linked to CI results | 1 |
| 🟧 No automation ref set | 0 |
| 🟥 Automation gap (ref, no CI match) | 1 |
| Automation gap % | 50.0% |

## Coverage by priority
| Priority | Total | Automated | Gap % |
|----------|-------|-----------|-------|
| critical | 1 | 1 | 0.0% |
| high | 1 | 0 | 100.0% |
```

- **Gap** = cases marked `execution_type: automated` whose `automation_test_id` matched no CI
  `code_ref`. Fix the ref or set `execution_type: manual` to close a gap.

## Automated launch — `reports/automated/<run>.json`

Normalized from a JUnit report by `ingest_results`.

```jsonc
{
  "launch": { "total": 2, "passed": 1, "failed": 1, "skipped": 0 },
  "items": [
    { "code_ref": "tests/e2e/cart.spec.ts:Cart.add", "name": "add",
      "status": "passed", "duration_ms": 1200, "failure_message": "" },
    { "code_ref": "tests/e2e/cart.spec.ts:Cart.checkout", "name": "checkout",
      "status": "failed", "duration_ms": 800, "failure_message": "expected 200" }
  ]
}
```
`status` ∈ `passed | failed | skipped`. `code_ref` is the automation identity used for correlation.

## Correlation — `reports/correlation.json`

Written by `correlate_results`: which automated results matched which cases.

```jsonc
{
  "matched": [
    { "case_id": "SHOP-0001", "code_ref": "tests/e2e/cart.spec.ts:Cart.add", "status": "passed" }
  ],
  "unmatched_refs": [ "tests/e2e/cart.spec.ts:Cart.checkout" ]
}
```
Matching normalizes both `automation_test_id` (case) and `code_ref` (result) to `file:Class.method`
(pytest `::` → `:`, whitespace removed, case-insensitive).

## Case index — `index.json`

Built by `build_index` from every test case's front-matter; backs `search_test_cases` and coverage.

```jsonc
{
  "cases": [
    {
      "id": "SHOP-0001", "title": "Add a product to the cart",
      "status": "ready", "execution_type": "manual", "type": "functional",
      "priority": "critical", "size": "M", "module": "cart", "owner": "",
      "tags": ["smoke","cart","happy-path"],
      "requirements": ["SHOP-REQ-001"],
      "automation_test_id": [], "targets": ["onetest-ai/tm-shop"],
      "dependencies": [], "known_issues": [],
      "path": "tests/cart/SHOP-0001_add-to-cart.md"
    }
  ]
}
```

See [test-case format](test-case-format.md) for the source fields and [OQL](oql.md) for querying the
index.
